# Research: LLM Reasoning Fine-Tuning Pipeline

**Branch**: `001-llm-reasoning-finetuning` | **Date**: 2026-04-16
**Revision**: 3 (rebuilt from competition intelligence)

## Training Data Strategy

**Decision**: Programmatically generate CoT traces from train.csv

**Rationale**: The competition benchmark contains 7 specific puzzle
categories with deterministic solutions. The winning approach (0.877
target, 0.85 achieved) generates all training data programmatically
using Python solvers — no external datasets, no distillation, no RL.
Each puzzle in train.csv (9500 samples) gets a step-by-step reasoning
trace generated by a category-specific solver.

**Alternatives rejected**:
- OpenMathReasoning: Domain mismatch — competition puzzles are bit
  manipulation, ciphers, and arithmetic, not standard math problems
- Distillation from larger models: Prohibited for closed models
  (Gemini, GPT-5). Open-source distillation possible but unnecessary
  when optimal traces can be generated deterministically
- RL (GRPO/DPO): Winner demonstrated SFT alone is sufficient when
  the target policy is already known. RL adds complexity without
  proven benefit for this task.

## Trace Generation Approach

**Decision**: Category-specific deterministic CoT traces

**Rationale**: Each puzzle type has a known solution algorithm. The
model needs to be taught to execute that algorithm step-by-step with
`<think>...</think>` reasoning and `\boxed{}` final answer. Key
design principles (from winning approach):
- **Deterministic**: temperature=0.0 means only the most likely
  token matters
- **Bit-serial**: For binary puzzles, spell out each gate operation
  one bit at a time (parallel = 9.3% accuracy)
- **Char-by-char**: For ciphers, decrypt one letter at a time
- **Multi-step arithmetic**: Break division into subtraction/addition
- **Within 7680 tokens**: All traces must fit the competition limit
- **Tokenization-aware**: Avoid patterns where tokenizer merges tokens

## Fine-Tuning Approach

**Decision**: QLoRA (4-bit base + bf16 LoRA, rank 32)

**Rationale**: Unchanged from previous revision. 30B model in 4-bit
quantization = ~17GB base. With LoRA adapters + optimizer + activations
= ~24GB total. Massive headroom on 96GB GPU.

**Training objective**: Maximize minimum logprob across training
traces (from winning approach). This ensures even the least-confident
token in every trace is still the most likely next token.

## Inference Framework

**Decision**: vLLM with competition parameters

**Rationale**: Competition uses vLLM to evaluate. Must match exactly.
`enable_thinking=True` is critical — model produces `<think>...</think>`
reasoning traces during evaluation.

## Answer Format

**Decision**: `\boxed{}` with category-specific formatting

**Rationale**: Competition metric extracts from `\boxed{}`. Format
requirements vary by category:
- Binary: 8-bit string (strict, no leading-zero tolerance)
- Gravity/Unit: X.XX (exactly 2 decimal places)
- Roman: Standard Roman numeral string
- Cipher: Plaintext phrase
- Equation: Numeric or string result
- Cryptarithm: Varies
